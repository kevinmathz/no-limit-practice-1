HARD CONSTRAINTS (every agent, every file)
-----------------------------------------------------------------------------------
1. TIME: act() < 1 ms. OUR GATE: 99.8th percentile of act() true cost <= 0.8 ms, and 0 failed
   decisions in local play. Passive fallback (check if free, else fold) when late is fine.
   - Heavy work only at import, then `import gc; gc.collect(); gc.freeze()`.
   - Direct-index numpy arrays for lookups (e.g. a 52^3 index array, not a dict of tuples).
   - Precompute per-cell tables instead of per-opponent numpy work, e.g.
     EQP[cell, my_class, opp_public_info] = equity vs that opponent's prior range; only fall
     back to vector math for opponents with showdown evidence.
   - Soft deadline: t0 at the start of act(); past 0.55 ms skip optional work and take the
     cheap action (chart action, or check/fold). Monte Carlo gets a wall-clock budget.
   - OMP/MKL/OPENBLAS/NUMBA_NUM_THREADS=1 before numpy. No threads at import.
2. STATE: nothing in self/globals between calls; per-table state only in `memory` bytes
   (fixed-size binary codec, < 8 KB, parsed defensively). No info across tables.
3. LEGALITY: only kinds in state.legal_actions; raise_to totals are ints in [min, max]
   (total = whole bet this round). Helpers: raise_to (clamp), jam, call_or_check,
   check_or_fold. Unknown phase -> Action(first.kind, first.min_amount).
4. IMPORTS: stdlib, poker_agent_sdk, poker_agent_protocol, numpy (+ the kit's allowed list).
   NEVER the kit engine or pokerkit, anywhere in the bot folder.
5. ROBUSTNESS: try/except around every layer; read everything from state.config.
6. PACKAGING: one WORK FOLDER: agent.py (literal `class Agent` with `act(self, state, memory)`)
   + one .npz of tables loaded via __file__. Develop modules separately in a scratch folder
   and generate agent.py with an amalgamator that embeds each module's source and exec's it
   into its own module namespace (no helper-name collisions); the Agent class subclasses the
   core agent so the checker sees it.
7. WRITE SCOPE: only the WORK FOLDER and the scratch folder; each subagent only its own
   files; no edits to the kit, other bots or shared repos; no git unless asked.

-----------------------------------------------------------------------------------
THE kevin_v1 ARCHITECTURE (build exactly these layers)
-----------------------------------------------------------------------------------
The game is a survival/placement tournament (50/30/20, 4th–8th = 0).
L1 VARIANT DECISION: equilibrium mixed policy from a QUICK solve (A2) over canonical
   (suit-isomorphic) classes, sampled with random.random(); heuristic mixed policy if A2
   isn't ready. Never let public info be a deterministic function of private info.
L2 TOURNAMENT VALUE (A3): exact top-3 Malmuth–Harville ICM vectorised over outcome rows;
   hero-only fast path; busted hero = place payout; jam_ev / call_ev / risk_premium; plain
   ICM at every horizon; exact rank settlement on the last hand only if the cap pays by rank.
L3 SHORT STACK <= 25bb: push/fold chart from A2 (keyed by position, our class, which card we
   made public, strongest public info of players behind / of the jammer), then the ICM check:
   jam if EV(jam) − EV(fold) > +0.15 pts, fold if < −0.15, else follow the chart mix.
   Callers' p_call = Σ posterior·chart_call_prob, scaled by observed call-vs-jam rate / 0.35
   (clipped to [0.5, 2]); eq = our equity vs that calling range. Facing a jam: call_ev with eq
   vs (posterior × chart jam prob), blended toward any-two by (jam_rate − 0.06)/0.25.
   Facing a non-all-in raise while short: re-jam if jam_ev > fold (raiser call prob
   0.35 + committed fraction), else fold.
L4 DEEP PREFLOP — 3-BET OR FOLD:
   - Unopened: open 2.5bb (+1bb per limper) if geometric-mean equity vs each player behind
     >= 0.50 + 0.012·(n_behind − 1) (SB vs BB alone 0.48); BB vs limpers raise to 4bb if > 0.62.
   - Facing a raise: raiser range = top (PFR/VPIP)·0.5^(raises−1) of their posterior, ×1.5.
     eq >= 0.58 + rp -> 3-bet to 3x (jam if 2+ raises or it commits > 35% of stack);
     BB defend if pot odds <= 0.30 and eq >= 0.50 + rp; call only if <= 6% of stack and
     eq >= 0.55 + rp (single raise); else FOLD. rp = risk_premium clipped to [−0.05, 0.15].
L5 POSTFLOP (A5): Monte Carlo vs each opponent's posterior hidden cards (their public cards
   exact), ≤ 30 samples, budget ≈ 0.2 ms minus time used, exact on the river.
   Facing a bet: eq_adj = eq · clip(1 − (1 − agg)·0.30·(0.5 + size), 0.45, 1.05);
   need = pot odds + rp (+0.06 if the call is >= 30% of stack); raise if eq_adj >=
   0.72 + 0.06·(opps − 1) + rp; call if eq_adj >= need; else fold.
   Checked to us: value bet 0.62–0.75 pot if eq >= max(0.42, 0.62 − 0.1·(opps − 1)) + 0.5·rp;
   jam if SPR <= 1.5 and eq >= 0.55; heads-up small bluff frequency only if rp < 0.08.
   rp computed only when the stake is >= 25% of our stack.
L6 OPPONENT MODEL (A5): per-seat counters + the variant's public-info habits linked to
   showdowns; posterior over hidden parts = equilibrium prior × bucket multipliers from
   showdown evidence (pseudo-count 15, pooled over similar ranks); action tilt for players
   who raised/jammed this hand.

-----------------------------------------------------------------------------------
DO NOT BUILD (measured no gain or harmful in practice)
-----------------------------------------------------------------------------------
- Loose deep flat calls (largest leak found; replaced by 3-bet-or-fold = +8.5 pts).
- Routing deep commit-sized raises through the ICM call path (tested −1.5 pts).
- Long CFR runs: full tables = quick tables (no measurable difference). Cap A2 at a quick
  solve. Never use a heads-up CFR abstraction at 8-max (our worst bot). No full-game MCCFR.
- Monte Carlo horizon/blind-steal/lock-in adjustments on top of ICM (artifacts, no gain).
- Rank-mode horizon modelling beyond the last hand (no gain); "shove the last hand" under
  ICM settlement (coinflips never gain under ICM).
- MDF defending, hand-picked bubble schedules (team tested: worse / no gain).
- Old weak postflop call shading (5%); per-opponent numpy loops and big dict tables (timing).
- Waiting on agents' report-writing or long diagnostics: stop them once outputs are in.

-----------------------------------------------------------------------------------
TIMING METHOD
-----------------------------------------------------------------------------------
(a) True cost: record 1000–3000 real states vs strong bots; time act() 15x per state, take
    the min; p50/p99/p99.8/max per phase. Gate p99.8 <= 0.8 ms.
(b) Raw: kit play p99 + failed decisions. Heavy background jobs cause 10+ ms preemption
    spikes even for trivial code; time on a quiet machine; cProfile the slowest states.
